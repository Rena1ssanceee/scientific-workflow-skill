# Candidate Direction Evaluation

## 1. Candidate format

Each candidate must be a complete scientific direction, not a technique.

Required fields:

- central question;
- biological or clinical rationale;
- evidence gap;
- data used;
- analysis unit and design;
- primary comparison or endpoint;
- analysis modules;
- validation strategy;
- expected evidence chain;
- novelty boundary;
- limitations and failure modes;
- feasibility class.

## 2. Internal evaluation dimensions

Evaluate candidates using the following default priorities:

- data fit: 25%;
- scientific-question coherence: 15%;
- evidence gap and differentiation: 15%;
- statistical reliability: 15%;
- validation conditions: 10%;
- completeness of the evidence chain: 10%;
- implementation complexity and risk: 10%.

The numeric score is an internal decision aid. Show it only when it helps the user compare directions.

## 3. Selection rules

Prefer a direction that:

- uses the defining data advantage;
- respects the independent unit and chronology;
- has a clear primary comparison;
- produces a connected result chain;
- supports validation without forcing incompatible datasets;
- avoids a crowded or directly overlapping research lane;
- can be completed without violating user constraints;
- supports claims at an appropriate strength.

Do not select a direction solely because it uses the newest algorithm.

## 4. Final-plan convergence

Select one primary direction. A secondary layer may be retained only if it directly strengthens the same question.

Avoid “analysis shopping lists” that contain diversity, machine learning, networks, pathways, and prediction without a shared scientific purpose.

## 5. Claim boundary

For the selected direction, explicitly state:

- what the study can establish;
- what it can associate;
- what it can only suggest;
- what it cannot infer without additional data or experiments.
